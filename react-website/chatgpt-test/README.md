# ChatGPT Integration

## Overview

The application integrates ChatGPT into the prescription-analysis workflow.

The purpose of the integration is to take a **prescription image uploaded by the user**, send that image through the backend to a dedicated ChatGPT processing pipeline, and receive a **structured JSON representation of the medicines detected in the prescription**.

The integration consists of three major layers:

```text
React Frontend
      │
      │ Image Upload
      ▼
Express / Node.js Server
      │
      │ Saved Image Path
      ▼
chatgptPipeline.js
      │
      │ Playwright
      ▼
ChatGPT
      │
      │ Structured JSON
      ▼
Node.js Server
      │
      ▼
React Frontend
```

---

# 1. Integration Architecture

The ChatGPT integration is divided into the following components:

### Frontend

The React application provides the user interface for:

* Selecting/uploading a prescription image
* Sending the image to the backend
* Waiting for analysis
* Receiving the extracted medicine information
* Displaying the result to the user

### Backend

The Node.js/Express server is responsible for:

* Receiving uploaded images
* Saving the uploaded file
* Determining the image's filesystem path
* Starting the ChatGPT pipeline
* Passing the image path to the pipeline
* Receiving the pipeline output
* Returning the result to the React frontend

### ChatGPT Pipeline

The standalone pipeline is located at:

```text
react-website/chatgpt-test/chatgptPipeline.js
```

This script is responsible for interacting with ChatGPT using Playwright.

### ChatGPT

ChatGPT performs the actual visual interpretation of the prescription.

The expected output is structured medicine data rather than arbitrary conversational text.

# 3. Frontend → Backend

The React frontend uploads the prescription image to the backend.

The image is sent as a multipart form-data request.

Conceptually:

```text
React
  ↓
POST /<analysis-endpoint>
  ↓
Express
  ↓
Uploaded image
```

The backend receives the file and stores it inside the server's upload directory.

The resulting file is available through a path similar to:

```text
server/uploads/<generated-file-name>
```

The filename may be generated by the upload middleware, so the backend should use the actual path returned by the upload process.

---

# 4. Uploaded Image Handling

The uploaded prescription image is temporarily stored on the server.

For example:

```text
react-website/
└── server/
    └── uploads/
        └── 8096673b14b9e33200332e9d28c732f9
```

The backend converts the uploaded file path into an absolute path before passing it to the ChatGPT pipeline.

Example:

```js
const imagePath = path.resolve(req.file.path);
```

This is important because the Playwright pipeline may execute from a different working directory.

Using an absolute path prevents the pipeline from depending on the directory from which Node was started.

---

# 5. ChatGPT Pipeline

The dedicated ChatGPT automation script is:

```text
react-website/chatgpt-test/chatgptPipeline.js
```

The pipeline is intentionally separated from the Express server.

This provides a clear separation between:

```text
HTTP/API logic
```

and:

```text
ChatGPT browser automation
```

The backend launches the pipeline and provides the uploaded image path as an argument.

Conceptually:

```bash
node chatgptPipeline.js <image-path>
```

For example:

```bash
node C:\...\react-website\chatgpt-test\chatgptPipeline.js C:\...\server\uploads\<image>
```

---

# 6. Why `chatgptPipeline.js` Is Separate

The pipeline is kept as a standalone Node.js script because it performs browser automation using Playwright.

This makes it easier to:

* Test ChatGPT interaction independently
* Debug browser automation
* Change the ChatGPT prompt without modifying the Express routes
* Run the pipeline manually
* Reuse the pipeline from the backend
* Keep frontend/backend logic separate from browser automation

The backend only needs to know:

```text
Where the pipeline is
+
Which image to give it
```

---

# 7. Playwright

Playwright is used by the pipeline to automate the ChatGPT web interface.

The general process is:

```text
Launch browser
      ↓
Open ChatGPT
      ↓
Authenticate using the configured session
      ↓
Open a conversation
      ↓
Attach prescription image
      ↓
Send analysis prompt
      ↓
Wait for ChatGPT response
      ↓
Extract response
      ↓
Parse structured JSON
      ↓
Return result
```

The pipeline therefore acts as the bridge between the application's backend and the ChatGPT interface.

---

# 8. ChatGPT Authentication

The Playwright pipeline requires an authenticated ChatGPT browser session.

Authentication should be handled through the browser/session mechanism used by the pipeline.

The application should **never store a ChatGPT password directly in source code**.

Sensitive authentication information must not be committed to GitHub.

Do not place credentials inside:

```text
chatgptPipeline.js
```

or any other tracked source file.

Sensitive configuration should be stored outside the repository.

---

# 9. Prescription Analysis

Once the prescription image reaches ChatGPT, the pipeline provides ChatGPT with an analysis instruction.

The instruction should make the expected response format explicit.

The important requirement is that ChatGPT returns machine-readable data.

The intended workflow is:

```text
Prescription Image
        ↓
Vision Analysis
        ↓
Medicine Identification
        ↓
Structured JSON
```

The pipeline then captures the response.

---

# 10. Structured Output

The integration expects medicine information in JSON form.

A conceptual response looks like:

```json
{
  "medicines": [
    {
      "name": "Medicine Name",
      "dosage": "500 mg",
      "frequency": "Twice daily",
      "duration": "5 days"
    }
  ]
}
```

The exact fields should match the schema implemented by the current pipeline.

The critical property of the output is that it is structured and predictable enough for the backend and frontend to process.

---

# 11. Why JSON Is Used

Returning structured JSON provides several advantages.

Instead of making the frontend interpret arbitrary ChatGPT text:

```text
Take this medicine twice daily...
```

the application receives machine-readable information:

```json
{
  "name": "...",
  "dosage": "...",
  "frequency": "...",
  "duration": "..."
}
```

This allows the frontend to directly display individual fields.

It also makes the integration easier to extend later.

For example:

```text
Medicine
 ├── Name
 ├── Dosage
 ├── Frequency
 ├── Duration
 └── Instructions
```

# 12. Backend ↔ Pipeline Communication

The backend launches the pipeline as a child process.

The important inputs are:

```text
Pipeline path
Image path
```

The pipeline writes its result to stdout.

The backend captures that output.

Conceptually:

```text
Express
   │
   │ spawn/exec
   ▼
chatgptPipeline.js
   │
   │ stdout
   ▼
Express
```

The backend can then return the result through the HTTP response.

The pipeline receives the prescription image path as its command-line argument.

Example:


Inside the pipeline, the argument is retrieved from Node's command-line arguments.

Conceptually:


Therefore:

```text
process.argv[2]
```

must contain the prescription image path.

# 16. Error Handling

There are several possible failure points.

### Upload failure

The image may fail to reach the server.

```text
React
  ↓
X
Express
```

The backend should return an appropriate HTTP error.

### Invalid image path

The uploaded file may not exist when the pipeline starts.

The pipeline should verify that the supplied path is valid.

### Playwright failure

The browser may fail to launch.

Possible causes include:

* Missing Playwright browser
* Browser crash
* Incorrect executable configuration
* Permission problems

### ChatGPT interaction failure

ChatGPT may fail to respond as expected.

Possible causes include:

* Authentication/session problems
* Page structure changes
* Network failure
* Unexpected UI state
* Response timeout

### JSON parsing failure

ChatGPT may return additional text around the JSON.

The parser must therefore handle the expected response format carefully.

---

# 17. Playwright Errors

When the pipeline fails, the backend may produce an error similar to:

```text
===== PLAYWRIGHT ERROR =====
```

This indicates that the child process running the ChatGPT automation encountered an error.

The full Node/Playwright error should be logged during development because it identifies where the pipeline failed.

Common debugging checkpoints are:

```text
1. Does the uploaded image exist?
2. Is the image path correct?
3. Does chatgptPipeline.js exist?
4. Can Node execute the pipeline manually?
5. Can Playwright launch?
6. Is the ChatGPT session authenticated?
7. Can ChatGPT receive the image?
8. Does ChatGPT return the expected response?
9. Can the pipeline parse the response?
10. Does the backend receive stdout correctly?
```

# 22. Important Limitation

The Playwright approach automates the ChatGPT website.

That means the integration depends on the current behavior of the ChatGPT web interface.

Changes to the ChatGPT UI can potentially break:

* Element selectors
* Upload controls
* Message submission
* Response extraction
* Authentication handling

Therefore, Playwright automation should be treated as a browser-automation integration rather than a stable API contract.

---

# 23. API-Based vs Browser-Based Integration

There are two fundamentally different ways an application can integrate with OpenAI models.

### Browser automation

Current architecture:

```text
Application
    ↓
Playwright
    ↓
ChatGPT website
    ↓
Model
```

Advantages:

* Can automate the existing ChatGPT web experience
* Useful for browser-based workflows

Disadvantages:

* UI-dependent
* More fragile
* Requires browser/session management
* More difficult to deploy reliably

### OpenAI API

API architecture:

```text
Application
    ↓
OpenAI API
    ↓
Model
    ↓
Structured response
```

Advantages:

* Designed for application integration
* No UI selectors
* No browser automation
* Easier to structure programmatic requests

The README should clearly identify which architecture the project currently uses.

# 30. Summary

The ChatGPT integration provides automated prescription-image analysis.

The React frontend handles the user interaction and image upload. The Express backend receives and stores the image, then starts the standalone `chatgptPipeline.js` process with the uploaded image's absolute path.

`chatgptPipeline.js` uses Playwright to interact with ChatGPT, provides the prescription image and analysis instructions, retrieves the response, and produces structured medicine information.

The backend receives that result and sends it back to React, where the extracted medicine information can be presented to the user.

The integration therefore follows this core pattern:

```text
Prescription Image
        ↓
React
        ↓
Express
        ↓
chatgptPipeline.js
        ↓
Playwright
        ↓
ChatGPT
        ↓
Medicine JSON
        ↓
Express
        ↓
React
```
